# GitHub 可见快照节奏

## 目的

本文件只规定项目的可见性节奏。提交与推送是给作者、审核者和协作者阅读的快照，不代表章节完成、Canon 定稿、审校通过或质量背书。

## 默认提交节点

每个章节设置两个正式快照节点：

1. 场景卡完成独立审校并同步索引后，提交并推送一次。
2. 正文完成独立审校并同步索引后，提交并推送一次。

如果一个章节跨越多个工作时段，且距离上次推送已经超过一个工作日，则增加一次 `checkpoint` 快照。checkpoint 可以是不完整草稿、审校中的卡片或结构调整，不把它写成“完成”。

## 提交命名

- `checkpoint: vol2 chXX scene card`
- `checkpoint: vol2 chXX prose`
- `checkpoint: vol2 chXX review`
- `checkpoint: project structure`

提交信息使用“当前看得见什么”命名，不使用“final”“done”或“canon locked”等会制造完成错觉的词。

## 推送范围

- 默认推送当前小说项目的结构化资料、场景卡、正文、审校记录、Canon 变更和工作日志。
- 不推送临时文件、凭据、私人附件或与小说无关的工作区改动。
- 推送到 GitHub 的默认远端为 `origin`；当前仓库默认分支为 `main`。
- 用户没有要求时，不自动创建正式 PR；可见快照以 commit 和 push 为主。
